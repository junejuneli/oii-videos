# 脚本 v3.1：AI 改图总「乱改」、听不懂人话？涂哪改哪

- 规格：**1440×1080（4:3）**，30fps，目标 **2:20–2:40**；B 站 / 小红书 / 视频号
- 配音：TTS 后续由用户加；本稿「配音稿」按约 4.5 字/秒写
- 依据：`research.md`（B 站「秋芝2046」及同类视频的字幕拆解 + 小红书搜索页）
- 状态：脚本稿，未录制，未生成案例图

## 一、为什么重写（v2 的问题）

| v2 的问题 | 调研里高播放视频怎么做 |
|---|---|
| 28s 铺垫才到功能，前 3 秒没有钩子 | **前 3 秒就是结果或痛点**；7 条结果快闪（“涨水了没有 / 起火了没有 / 去掉椅子 / 加个外星人”）；或“PS 半小时 vs 现在 3 步” |

| 没有看完的理由 | 前置利益点（提示词/文档）+ 编号让观众知道“还剩几个” + 压轴 |

## 二、AI 局部编辑的真实痛点（用户语言）

| 痛点 | 用户怎么说 | 视频里怎么出现 |
|---|---|---|
| **听不懂人话**：说不清「哪里」 | “局部修改听不懂人话” | 开场：你打一大段字描述位置，它还是改错地方 |
| **乱改**：不该动的也动了 | “总乱改”“先说清楚哪些别动” | 开场对照 + 每个案例的“只有这里变了” |
| **穿帮 / 错位** | “局部重绘总穿帮” | 案例结果特写：边缘自然、光影一致 |
| **要自己想办法** | “绿幕 + P 图”“圈选标注”“先分区再改” | 一句话带过：“以前要用绿幕、要写一堆‘保持其他不变’” |

> 这几个痛点同行视频里已经被反复验证，不是 OiiOii 视角。解法只有一句：**涂（圈）出来，直接告诉它「就是这儿」。**

## 六、Tips 文档（简介 / 置顶评论里提供）

已确认：我们会提供小技巧 Tips 文档。建议内容，一个案例一小节，和画面里的“小技巧”一一对应：

| 案例 | Tips 要点 |
|---|---|
| 1 去路人 | 涂抹范围略大于路人；「擦除」一句话就够；背景复杂时多涂一点边缘 |
| 2 修手 | 涂多了用橡皮擦，不满意撤销；描述写“五指自然”比“修好”更准 |
| 3 改错字 | 笔刷调小，涂整个词；文案越短越稳 |
| 4 换颜色 | 颜色说具体（酒红 > 红）；每次从原图出发再换下一个颜色 |
| 5 改表情 | 明确的一块区域用框选；只框脸，其余不动 |
| 6 换道具 | 说材质、颜色、大小；位置用框选 |
| 7 多处 | 一次涂多处，再统一说一句 |
| 8 连环改 + 引用 | 每一步只动一处；有参考图用「引用」或「上传」，别硬写 |
| 通用 | 涂抹 vs 框选怎么选；提示词的几个句式；积分 / 时间参考 |

每个案例同时附：**原图**（让观众可以跟着做）和**提示词原文**。

## 七、制作要点

1. **4:3 画面**：视口约 1029×772（2 倍 = 2058×1544），缩放到 1440×1080；需验证智能编辑工具条和输入框放得下。
2. **每个案例单独录一段**；快闪蒙太奇和差异高亮后期合成。
3. **图可以 mock**（用户确认）：画布里的案例图后续从网上找，先不依赖生成。0–3s 的“乱改”对照做成**示意**，字幕可加“示意”小字；常见现象有大量用户反馈（见 research.md）。
4. **差异高亮**（DiffReveal）：像素差异，只亮出被改区域，其余压暗。
5. 保真是卖点：每个案例结果都放大 1 次看边缘和光影。
6. **待实测**：框选 vs 涂抹的区别；生成结果覆盖原节点还是派生；一次涂多处；引用局部的准确度；撤销 / 橡皮擦；连改四次是否稳定。
7. 新组件（先写在视频的 `src/`）：前后对比快闪（FlashCompare）、差异高亮（DiffReveal）、案例标签（n/8）、简介卡。
