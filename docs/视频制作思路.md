# 视频制作思路

本项目做两类视频，思路不同，开工前先在 `brief.md` 里写明属于哪一类。

| | A. 功能介绍 | B. 自媒体教程 |
|---|---|---|
| 时长 | 约 1 分钟 | 1–10 分钟 |
| 口播配音 | 无，靠画面 + 字幕 + BGM | 有，口播是主线 |
| 目的 | 让人一眼看懂"这个功能能干嘛" | 让人学会"怎么做出一个结果" |
| 信息载体 | 步骤字幕、高亮、成片 | 口播 + 屏幕演示 + 章节卡 |
| 画面主体 | 画布录屏一镜到底 | 录屏 / 成片 / 少量真人或形象口播 |

---

## B. 自媒体教程视频

> 参考样本（2026-10 调研）：秋芝2046《从零开始，学会让桌面Agent帮你干活》（13 分钟，137 万播放）、李一帆AIGC《别再靠抽卡，白模让AI视频更听话》（8 分钟，8.4 万）、《剪视频太浪费时间？我让Codex把剪辑流程跑完了》（5 分钟，2.2 万）。
> 限制：没有拿到字幕和音频，以下来自标题简介、抽帧缩略图（约 5–8 秒一帧）和弹幕，口播语速、BGM 未量化。

### 1. 标题与简介

- 标题公式：**痛点 + 工具 + 结果**，例如"别再靠抽卡，白模让 AI 视频更听话"。
- 简介前两句写痛点，写成"你想……AI 偏……"的对比句；再写"从 A 变成 B"的一句话价值。
- 弹幕里"求文档"、"三连求文档"出现频率很高：**每期配一页文字版步骤和提示词**，放简介或置顶评论。

### 2. 结构骨架

```
0:00  成片预览（5–10 秒，闪 3–4 个最终镜头）
0:10  口播抛痛点 + 本期你会得到什么（20–30 秒）
0:40  Step 1 → Step 2 → … → Step N   （每步 40–90 秒）
末尾  成片完整展示 + 一句话总结 + 引导（15–30 秒）
```

- 步数控制在 3–5 步；超过就拆成两期或归并成"大步骤 + 小技巧"。
- 8 分钟以上的视频，中段可以加一次"小结 / 常见坑"，帮观众重新对齐。

### 3. 节奏

- **口播人像只做衔接**：开头、每个章节起点、结尾出现，合计约 1/5 时长；中间 70–80% 是屏幕演示或成片素材。
- **每 5–10 秒有一次画面变化**：局部放大、标注框、对比图、素材切换，不要让同一画面静止超过 10 秒。
- **每一步结束必须出结果**：演示 → 立刻展示这一步生成的效果（停留 1–2 秒）→ 回到口播或下一步。
- 等待生成的时间一律加速或砍掉（见 `oii-one-take-edit`）。
- 同一个案例贯穿全片，比每一步换一个例子更容易让人跟下来。

### 4. 包装

- **章节卡**：黑底大字 `Step 1 · 一句话主题`，2 秒左右，风格和品牌包装统一（`oii-brand-package`）。
- 重点操作用高亮 / 流光框 / 点击涟漪（`oii-highlight`），一次只强调一个元素。
- 屏幕下方加一行**口播字幕**，字号要比步骤字幕小，两者不要重叠。
- 前置一个 3 秒内能看到的标题花字，不要只靠封面。
- 封面：沿用 `oii-brand-package` 里的封面规范，主标题 ≤ 12 字，配最能代表结果的一帧。

### 5. 口播配音

- 先写稿再录屏：稿子按 Step 切段，每段对应一个画面块，方便后期对时间轴。
- 句子短、口语化，一句话只讲一个动作；避免连续 3 句以上没有画面变化。
- 配音先出整段母版，再按稿子切段对齐画面；改稿只重录对应段落。
- 响度统一 -16 LUFS（沿用 `oii-render-release`）。BGM 在口播下压低，章节卡和成片展示处抬起。

### 6. 制作流程

1. `oii-video-new`：写 `brief.md`，注明类型 B、目标时长、目标观众、本期"结果"是什么。
2. 写口播稿 + 分镜表（Step、画面来源、时长、字幕/高亮点）。
3. 录制素材：画布录屏（`oii-canvas-record`）、成片素材、必要的真人/形象口播。
4. 配音。
5. 剪辑：口播段、录屏段、成片段按分镜拼接，加速等待段（`oii-one-take-edit`）。
6. 标注和章节卡（`oii-highlight`、`oii-brand-package`）。
7. 出片（`oii-render-release`）。改意见按 `oii-feedback-loop`。
8. 整理配套文档（步骤 + 提示词），和视频一起发布。

### 7. 自检清单

- [ ] 前 10 秒能看到最终效果。
- [ ] 前 30 秒讲清"为什么要看"。
- [ ] 每个 Step 都有章节卡和一个可见结果。
- [ ] 没有超过 10 秒的静止画面。
- [ ] 没有超过 15 秒的纯口播人像。
- [ ] 配套文档已准备。

## A. 功能介绍视频（无口播）

- **一个视频只讲一个功能**，约 1 分钟，开头 3 秒内出现功能名，不铺垫。
- 靠画面讲故事：一镜到底的画布录屏 + 步骤字幕（`oii-brand-package`）+ BGM，不依赖解说。
- 结构：功能名 / 痛点一句话 → 3–4 个操作步骤（每步一行字幕）→ 成片 → 落版（Logo + 合作方）。
- 每一步字幕只写动作和结果，一行 ≤ 15 字；停留时间要够读完（约每 4 字 1 秒，最短 1.5 秒）。
- 操作演示要流畅，不让观众看到等待；用 `oii-one-take-edit` 做加速和遮盖。
- 重点用流光框强调，一次一个。

## 两类的复用

- 章节卡 / 步骤字幕 / 高亮 / 落版都用同一套品牌包装，B 类比 A 类多"口播字幕"和"章节卡"。
- 录屏、剪辑、标注、渲染流程相同，差别在于 B 类多了稿子、配音和成片素材的拼接。
- 同一个功能可以先做 A 类，再用它的素材扩展成 B 类教程。
