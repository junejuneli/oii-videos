# 反馈迭代

## 1. 定位

用户说的“第 Ns”是指成片的时间。换算成帧：`f = N × 30`。然后：
- 渲染这一帧：`npx remotion still <CompId> /tmp/f.png --frame=f`，先看清楚用户说的是哪个画面；
- 在 Promo.tsx 里找到对应的镜头：根据 `take.span` 或 Sequence 名称反查是哪个 `TakeShot`、哪个 overlay。
- 如果涉及录屏内容，换算出录屏秒数，回到原始帧去看。

## 2. 修改

- 一条反馈对应一处修改，不要顺手改别的地方。如果发现其他问题，单独列出来问用户。
- 文案严格用用户给的原话。如果觉得原话有问题，保留原话并提出建议，不要擅自改。
- 用户说“去掉某个动作”时，优先考虑剪掉对应的录屏片段（参见 oii-one-take-edit），而不是用遮罩盖住。

## 3. 自查

- 每条修改都渲染对应时间点的单帧，或者渲染一小段，亲自看过。
- 半尺寸完整渲染一遍，生成每秒一帧的拼图，检查有没有引入闪变或跳帧。
- 改了时间轴（镜头时长）后，后面所有按时间点描述的位置都会移动，回复时要告诉用户新的时间点。

## 4. 回复

- 逐条编号回复，和用户的反馈编号一一对应：改了什么，现在在第几秒。
- 有没做或者做法不同的地方要明确说出来，并说明原因。
- 在 brief.md 的迭代记录里加一节 `### vN`，记下反馈原话的要点和改动。

## 过往反馈沉淀的经验

- 用户说“先记下”：只写进 brief 的待办（文案定稿、贴纸计划等），不改代码、不出片；下一次出版本时一并应用并在回复里说明。
- 文案先给 3–5 个备选再定，用户会挑或混搭；定下来的要回填 brief。
- 用户按成片时间点给反馈时，先截那几个时间点的帧确认指的是哪个画面（比如“21s 的框”其实是颜色栏而不是圆点）。
- 贴纸/花字的出现时机要逐帧核对结果真正出现的那一帧。
