# 新建视频

## 1. 问清楚（只问会影响做法的）

- 宣传哪个功能？一句话核心卖点是什么？（例：“快速低成本出多个样片，挑一条成片”）
- 给谁看、发在哪里：决定时长和画幅（16:9 1920×1080 / 9:16 1080×1920 / 1:1）
- 素材从哪来：录画布操作 / 用户提供的成片和图片 / 纯动效
- 是否需要真的触发生成（会消耗积分）

## 2. 建目录

```bash
pnpm new <kebab-slug> "标题"     # -> videos/YYYY-MM-<slug>/
pnpm install
pnpm --filter <slug> dev
```

模板里已经带好了水印、渐黑和片尾 Logo。

## 3. 写 brief.md

填写目标、素材表、分镜结构表。用户给的原始素材放到 `public/raw/`，在素材表里写明来源。

## 4. 定脚本时就拆出“核心操作 → 核心结果”，写强调计划

功能介绍视频的主角是**操作**和**操作带来的结果**。写分镜时先把功能拆成 4–6 个核心步骤，每一步都回答三个问题，填进 brief 的「强调计划」表：

| 步骤 | 核心操作（光标在做什么） | 核心结果（画面上出现什么） | 操作强调 | 结果强调 | 结果停留 |
|---|---|---|---|---|---|
| 01 添加颜色标签 | 选中图片 → 点 toolbar 标签按钮 → 选绿色 | 标题前出现绿点 | 流光框圈按钮 + 粉色花字「👆 添加颜色标签入口」 | 绿色贴纸「✓ 已标记」+ 推近特写 | 1.8s |

规则：
- **每个核心步骤：一个操作强调 + 一个结果强调**，不多不少。非核心的过渡（拉远、平移、等待）不加任何贴纸。
- **操作强调** = 流光框圈住要点的 UI（按钮、列表项、颜色栏）+ 粉色花字说明“这是什么入口/在做什么”。花字在光标移向目标时出现，点击后消失。
- **结果强调** = 黄/绿贴纸，在结果出现的那一帧弹出，贴在结果旁边；同时这段镜头要放慢、多停 1.5–2s 让观众看清。
- 全片贴纸 + 花字控制在 10 个以内；同一个结果只说一次（贴纸和说明框不要重复说同一句）。
- **用词照搬产品界面**：先看产品里按钮、菜单、面板上的原文（如“添加颜色标签”“标记”“取消标记”），视频里的步骤名、花字、贴纸都用这些词，不要自己发明口语（反例：把“添加颜色标签”说成“贴标签”）。
- 开头一句痛点 + 结尾一句 slogan，都在脚本阶段给用户 3–5 个备选。

### 必备：1–2 个玩梗 / 热门话术

每个视频在脚本阶段就设计好 1–2 句有梗的话术，写进 brief 的「玩梗设计」，和强调计划一起确认：
- **放在哪**：最适合开头痛点（抓注意力，配 `MemeTitle`），其次是最“爽”的那个结果时刻（贴纸）。不要放在需要看清操作的地方。
- **怎么想**：先找功能解决的那个“抓狂瞬间”，再套大家熟悉的句式或热梗，让人一眼认出原梗、又贴合场景。
  - 经典句式改写：「我的图呢？我那么大一张图呢？」（我那么大一个 X 呢）、「生成一时爽，找图火葬场」（X 一时爽，Y 火葬场）
  - 拟人/吐槽：「眼睛：我已经尽力了」「素材：我就在这，你倒是找啊」
  - 夸张对比：「找图的时间，够再生成十张了」
  - 结果爽点：「唰～全亮了」「嗖～一键直达」
- **给备选**：至少 3 个方向（经典句式 / 拟人吐槽 / 夸张对比），每个注明梗的出处和放在哪个镜头，推荐 1–2 个让用户挑。
- **分寸**：梗为功能服务，一听就懂；避开低俗、地域、时效太短的梗；太重的词给温和替代（如“火葬场”→“找到断肠”）。

录制前和用户确认这张表：它决定了录屏里每个操作之间要留多少停顿、哪些结果要多录几秒。

## 什么时候往 kit 里加东西

只在第二个视频也要用到某个组件时才把它抽进 `packages/kit`，改 kit 时要确认已有视频的渲染没有变化（`pnpm typecheck`，并渲染旧视频的几帧对比）。
